# RA2IniEditor.IDE v0.5.0-preview 已知问题

## DeepSeek 请求仍可能超时

DeepSeek 默认请求超时已从 60 秒调整为 120 秒，并会显示独立的超时状态。网络、代理、服务负载或较长输出仍可能导致超时。当前版本不会自动重试，以避免重复请求和额外费用；需要时可设置 `DEEPSEEK_TIMEOUT_SECONDS` 后重新发送。

超时、取消或失败后，失败卡片会提供“恢复提示词”。它只在输入框为空时恢复原提示文本，不会自动发送，也不会覆盖已有输入；用户再次点击发送时仍可能产生服务费用。该次失败请求的用户提示和助手轮次都不会进入下一次请求的对话上下文。

应用层超时现在是唯一超时权威；共享 HTTP 客户端不会再用自己的默认超时提前终止请求。点击取消后，发送状态会在请求完成取消收尾后恢复，这是防止重复请求的预期行为。

当前版本会把配置、鉴权/授权、限流、请求拒绝、provider 超时、服务不可用、网络/代理、本地总超时、流空闲超时、协议错误和响应超限显示为不同的安全提示。提示不会包含 provider 错误正文、原始异常 Message、API Key、endpoint/代理详情或堆栈。该分类用于帮助判断下一步，但不是网络诊断工具；代理、DNS、防火墙和 provider 账户状态仍需在应用外确认。

自动重试仍未实现。这是有意保留的限制：在没有请求幂等性、费用和退避契约前，自动重放可能产生重复请求或额外费用。

AI 助手当前只提供 DeepSeek V4 Flash / V4 Pro，默认 Flash，并显式使用非思考模式。配置状态只显示可用性和官方/自定义端点类别，不显示 API Key 或完整地址；若配置无效，需要在应用外修正环境配置后重新打开面板或再次发送。

输入超过 8000 字符会在联网前被拒绝并完整保留。回答结构过大时会降级为只读纯文本显示，内容仍可选择和复制，但不会继续创建大量 Markdown 控件。

## AI 流式响应仍受请求超时和桌面刷新节奏限制

DeepSeek 响应现已通过 SSE 增量显示。桌面端会按约 50ms 或 512 个待显示字符合并刷新，以避免每个 token 都触发一次 WPF Dispatcher 更新，因此视觉刷新不是逐 token 的。

取消、超时、长度限制、内容过滤或服务异常时，已经接收的文本会保留并明确标记为不完整或错误。失败请求的用户提示和助手轮次都不会进入后续对话上下文。当前仍不自动重试；真实网络环境下的首段等待时间仍取决于 DeepSeek、代理和服务负载。


## 1. 字段库仍包含推断型字段

BuiltIn 中有部分字段来自社区资料辅助推断、字段名推断或人工整理。它们用于降低 Unknown Key 误报，但不代表官方逐条核验结论。

遇到推断字段时，Hover 会尽量只显示轻量提示，详细可信度请查看 Field Quick Peek 或字段库说明文档。

## 2. 仍可能出现 Unknown Key

Unknown Key 并不一定表示字段无效。可能原因包括：

- 当前 MOD 自定义字段。
- Ares / Phobos 新版本扩展字段尚未收录。
- 字段写在错误上下文。
- 字段属于脚本、注册列表或伪字段。

## 3. WrongContext 诊断可能不完整

当前 WrongContext 主要依赖 BuiltIn guardrail 和上下文匹配规则。它能覆盖一部分常见错误，但还不能保证识别所有上下文误用。

## 4. UI 自动化测试默认跳过

UI Automation smoke 默认跳过。若需要运行，应在交互式桌面会话中设置：

```powershell
$env:RA2INIEDITOR_RUN_UI_AUTOMATION=1
```

再运行对应测试。

AvalonDock 浮动 Search 的宿主 Chrome 可由 UIA 识别，但当前外部自动化树无法穿透到其内部 WPF 控件；这不影响普通键鼠使用，但限制了端到端 FlaUI 覆盖。

## 4.1 Search 范围限制

项目查找只扫描项目浏览器已经发现的顶层 `.ini` 文件，不递归扫描子目录。大于 8 MB 的延迟预览文件会跳过并在状态中报告。Replace All 仅支持当前文件，不提供项目级或多文件替换。

## 5. 不提供在线字段查询

当前所有字段信息均来自离线 BuiltIn / Global / Project 字段库。不会在运行时联网查询 ModEnc、Ares 或 Phobos 文档。

## 6. 不提供资源编辑能力

本版本不包含：

- MIX 浏览 / 解包。
- VXL / HVA 编辑。
- SHP 编辑。
- 地图编辑。
- 规则对象可视化完整工作台。

## 7. 保存前检查不是强阻断

即使 Issues 面板存在警告，用户仍可保存。这是刻意设计，避免 BuiltIn 字段库误判影响 MOD 作者的自由编辑。

## 8. Preview 发布包仍需要真实项目烟测

虽然 build / test 已通过，但不同 MOD 文件夹结构、字段风格、编码和体量都可能不同。建议正式使用前先在备份副本上试用。
