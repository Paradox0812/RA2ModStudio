# RA2IniEditor.IDE v0.5.0-preview 用户说明

## AI 助手与 DeepSeek 上下文说明

- AI 助手只提供 DeepSeek V4 Flash / V4 Pro，默认使用 V4 Flash；只有点击发送时才会发起请求。
- 模型选择是本次请求的唯一模型权威，不再接受环境变量覆盖。
- 受限上下文可能包含当前文档的选区或附近行、当前 Section/字段、字段证据、诊断摘要和最近对话。
- AI 助手不会因此读取整个项目，也不会自动修改、插入或保存文件。
- 输入超过 8000 字符时会在请求开始前拒绝，完整输入仍保留在输入框中，不会静默截断或联网。
- DeepSeek 默认请求超时为 120 秒，可通过 `DEEPSEEK_TIMEOUT_SECONDS` 调整；超时不会自动重试。
- 同一时间只允许一个 AI 请求。点击取消后，界面会等待当前请求真正结束再恢复发送，避免重复请求。
- DeepSeek 回答会通过 SSE 增量显示；桌面端约每 50ms 或累计 512 个待显示字符刷新一次，因此不是机械的逐 token 刷新。
- 取消、超时或服务错误时，已经收到的回答仍会显示并可复制；该次用户提示和助手轮次都不会作为下一次提问的对话上下文。
- 失败卡片上的“恢复提示词”只会把原提示恢复到空输入框，不会自动发送，也不会覆盖已有内容。再次发送使用当前模型和当前 IDE 上下文，并可能产生服务费用。
- DeepSeek 失败时，界面会区分配置缺失、鉴权/授权、限流、请求被拒绝、服务端超时、服务不可用、网络/代理、本地总超时、流空闲超时、协议异常和回答过长，并给出固定的安全提示。
- 出于安全考虑，界面不会显示服务端错误正文、API Key、请求地址/代理详情、原始异常信息或堆栈。若回答已接收一部分，现有文本会保留，并额外标注“以上内容可能不完整”。
- 失败分类只用于当前请求的界面提示，不会保存到项目、字段库或对话历史，也不会触发自动重试。
- 聊天历史和 Markdown 结构控件有硬上限；超限回答会降级为完整、只读、可选择复制的纯文本，避免界面资源无限增长。


## 1. 软件定位

RA2IniEditor.IDE 是面向《红色警戒 2 / 尤里的复仇》以及 Ares / Phobos 扩展 MOD 的 INI 辅助编辑器。当前版本重点提供：

- 项目文件夹浏览与 Source Editor 查看 / 编辑。
- Section Navigator 快速跳转。
- 字段 Hover 说明。
- Field Quick Peek 字段详情。
- Completion / Add Property 预览式字段补全入口。
- Issues 面板中的 Unknown Key、上下文错误、废弃字段和未实现字段提示。
- BuiltIn / Global / Project 字段库管理。
- 保存、备份、撤销、重做与 Revert 基础流程。

本版本是 `v0.5.0-preview`，适合内部测试和字段库质量验证，不应被视为最终稳定版。

## 2. 适用对象

适合以下使用场景：

- RA2/YR MOD 作者想减少手写 INI 时的字段名错误。
- Ares / Phobos 字段使用者想获得基础 Hover 和诊断提示。
- 工具开发者想验证 RA2 INI IDE 化工作流。
- 字段库维护者想测试 BuiltIn / Project 字段覆盖和导入流程。

暂不适合以下用途：

- MIX 浏览、资源提取、VXL / SHP / 地图编辑。
- 完整可视化对象工作台稳定生产使用。
- 完全权威的字段百科替代品。

## 3. 打开项目

1. 启动 `RA2IniEditor.IDE.exe`。
2. 点击菜单：`文件 -> 打开项目...`。
3. 选择包含 `rulesmd.ini`、`artmd.ini`、`aimd.ini` 或其他 RA2/YR INI 文件的 MOD 文件夹。
4. 在右侧项目浏览器中选择文件。
5. 中央 Source Editor 会显示当前文件内容。

建议先用备份副本或测试 MOD 文件夹进行试用。

## 4. Source Editor 基础使用

Source Editor 以文本方式展示 INI 文件。当前版本保留接近代码编辑器的工作流：

- 可直接编辑字段值。
- `Ctrl+S` 保存当前文件。
- 支持撤销 / 重做。
- 修改后切换文件会触发 dirty navigation 保护。
- 保存时会生成备份，便于回滚。

保存前检查是提示型，不是强阻断。即使存在诊断问题，用户仍可按自己的判断继续保存。

## 5. Navigator 使用

左侧或中间导航区域会列出当前文件的 section。点击 section 后，Source Editor 会滚动到对应位置。Navigator 只针对当前已加载文件，不跨文件跳转。

## 6. Hover 使用

鼠标悬停在字段名上时，IDE 会显示字段类型、说明和示例。

设计原则是保持轻量：

- 普通已核验字段不会显示冗长来源信息。
- 推断型字段只显示一行短提示：`可信度：推断说明，仅供参考。`
- 上下文保护字段会提示疑似写错位置。
- 废弃或未实现字段会提示不建议作为正常字段使用。

例如：

```ini
[General]
BaseDefenseDelay=.25
```

Hover 应解释为：AI 基地受到威胁后派出基地防御响应队伍的延迟时间，单位为分钟；`.25` 约为 15 秒。

## 7. Field Quick Peek

Field Quick Peek 用于查看比 Hover 更完整的字段信息。它适合查看：

- 适用上下文。
- 字段类型。
- 示例值。
- 字段可信度摘要。
- 是否为推断字段、guardrail 字段、废弃字段或未实现字段。

完整来源和质量信息不会默认塞进 Hover，避免编辑时过于繁杂。

## 8. Completion / Add Property

当前 Completion / Add Property 仍偏预览性质，重点用于快速查看可用字段和插入候选。字段候选来自 BuiltIn / Global / Project 组合字段库。

如果字段来自 Project 或 Global 字段包，并且上下文匹配，它可以覆盖 BuiltIn fallback。

## 9. Issues 面板

Issues 面板用于展示当前文档的诊断。当前版本开始区分以下风险：

| 类型 | 含义 |
|---|---|
| Unknown Key | 当前字段库无法识别该字段 |
| Wrong Context | 字段存在，但不建议写在当前 section / object 中 |
| Obsolete Key | 废弃字段 |
| Non-Existent Key | 原始注释残留或引擎未实现字段 |
| Pseudo Field | 注册列表或伪字段，不应作为普通 key 使用 |

推断型字段默认不会刷屏污染 Issues，只在 Hover / Quick Peek 中轻提示。

## 10. 字段可信度

字段库不是单一权威来源。当前 BuiltIn 字段分为几类：

- 来源核验字段。
- 上下文保护字段。
- 社区资料辅助推断字段。
- 字段名推断字段。
- 人工整理字段。
- 自动抽取残留字段。
- 废弃 / 未实现 / 伪字段保护项。

详细解释见 `FieldRegistryTrustLevels.md`。

## 11. Field Registry Manager

字段库管理器用于管理本地字段包。字段来源优先级大体为：

```text
Project > Global > BuiltIn
```

其中 Project 字段包适合当前 MOD 项目特有字段，Global 字段包适合用户通用字段扩展，BuiltIn 是 IDE 自带保底字段库。

## 12. 保存、备份与 Revert

保存当前文件时，IDE 会尽量保留文本编辑语义，并生成备份。Revert 用于放弃内存修改，回到保存基线。

建议测试期保留自己的 MOD 文件夹备份，不要直接在唯一工作副本上试用 Preview 版本。

## 12.1 窗口布局与恢复

- 停靠面板的位置、顺序、显示/隐藏、自动隐藏和浮动状态会在正常关闭后保存，并在下次启动时恢复。
- 布局只保存在当前 Windows 用户的本机配置目录，不会写入 MOD 项目，也不会保存编辑器文本、搜索结果、AI 对话或字段库数据。
- 工具栏和“视图”菜单中的“窗口布局”提供“将浮动窗口全部归位”和“恢复默认布局”。恢复默认布局成功后会立即覆盖本机布局文件。
- 布局文件无效、过大、不兼容或来自已断开的显示器时，IDE 会安全回到编译默认布局或当前显示器，不会阻止启动或关闭。

## 12.2 项目查找与当前文件替换

- “整个项目”只搜索项目浏览器已经列出的顶层 `.ini` 文件；不会递归扫描目录。
- “当前文件”使用编辑器内存文本，因此尚未保存的修改也能被搜索。
- 支持区分大小写、全字匹配和带超时保护的 .NET 正则表达式。
- 双击结果、按 Enter 或使用上一个/下一个可导航到文件、行和列。
- 替换仅支持当前文件：先“预览”，再“应用”；文档在预览后变化时必须重新预览。
- 应用只修改内存，不自动保存；整批替换可用一次 Ctrl+Z/Ctrl+Y 撤销或重做。

## 13. 常见问题

### 为什么还有 Unknown Key？

可能原因：

- 这是 MOD 自定义字段。
- 该字段来自尚未覆盖的 Ares / Phobos 扩展。
- 字段写在错误 section 中。
- 当前 BuiltIn 字段库尚未收录。

可通过 Project 字段包补充。

### 为什么 Hover 说“推断说明”？

表示该字段不是逐条官方核验，而是根据社区资料、字段名或上下文推断，用于降低误报，但不保证完全权威。

### 为什么保存没有被诊断强制阻止？

这是刻意设计。RA2/YR MOD 字段来源复杂，IDE 不应把 BuiltIn 当作强制权威规则。保存前检查保持提示型。
